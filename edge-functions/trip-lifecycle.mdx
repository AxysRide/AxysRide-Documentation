# Trip Lifecycle Edge Functions

## create-trip

Creates a new trip after validating the driver is approved, the departure time is in the future, and the price is within the platform cap for the route distance.

**Who can call:** Approved drivers only

### Request

| Field                 | Type       | Required | Notes                                                     |
| --------------------- | ---------- | -------- | --------------------------------------------------------- |
| `driver_id`           | uuid       | ✅       | Must match an approved driver                             |
| `start_location`      | object     | ✅       | Must include `latitude`, `longitude`, and `name`          |
| `end_location`        | object     | ✅       | Must include `latitude`, `longitude`, and `name`          |
| `price_per_seat_kobo` | integer    | ✅       | Driver sets this — validated against platform cap         |
| `total_seats`         | integer    | ✅       | Between 1 and 10                                          |
| `departure_time`      | ISO string | ✅       | Must be in the future                                     |
| `trip_type`           | string     | ❌       | `once` (default) or `recurring`                           |
| `notes`               | string     | ❌       | Optional driver notes e.g. "AC available"                 |
| `recurrence_days`     | integer[]  | ❌       | e.g. `[1,3,5]` for Mon/Wed/Fri — only for recurring trips |

```json
{
  "driver_id": "uuid",
  "start_location": {
    "latitude": 6.5244,
    "longitude": 3.3792,
    "name": "Ikeja"
  },
  "end_location": { "latitude": 7.3776, "longitude": 3.947, "name": "Ibadan" },
  "price_per_seat_kobo": 150000,
  "total_seats": 3,
  "departure_time": "2025-03-15T08:00:00Z",
  "trip_type": "once",
  "notes": "AC available"
}
```

<Warning>
  `start_location` and `end_location` must include a `name` field. This is
  stored as the human-readable origin and destination shown to passengers.
  Requests without `name` will be rejected.
</Warning>

### Response

```json
{
  "trip": {
    "id": "uuid",
    "status": "scheduled",
    "origin_name": "Ikeja",
    "destination_name": "Ibadan",
    "seats_available": 3,
    ...
  }
}
```

<CodeGroup>

    total_seats: 3,

    trip_type: 'once',
    notes: 'AC available',
  }
})

if (error) console.error(error)
const trip = data.trip

````

### Price Validation

Drivers set their own price freely. The function validates it against a platform cap derived from the route distance:

```
max_allowed = base_price_per_km × distance_km × max_multiplier
              capped at max_price_per_seat_kobo
```

Distance is calculated using the **Haversine formula** (straight-line approximation) via the `calculate_distance_km` database function. If the driver's price exceeds the cap, the request is rejected with the exact maximum allowed price in the error message.

### Errors

| Status | Message                                                                                             |
| ------ | --------------------------------------------------------------------------------------------------- |
| 400    | Missing required fields. start_location and end_location must include latitude, longitude, and name |
| 400    | departure_time must be in the future                                                                |
| 400    | total_seats must be between 1 and 10                                                                |
| 400    | Price per seat exceeds the allowed limit of ₦X,XXX for this route                                   |
| 403    | Driver not approved or not found                                                                    |
| 500    | Could not calculate trip distance                                                                   |

## start-trip

Starts a scheduled trip. All accepted passengers must have their PIN verified (or be marked as no-show) before the trip can start.

**Who can call:** Driver who owns the trip

### Request

```json
{
  "driver_id": "uuid",
  "trip_id": "uuid"
}
```

### Response

```json
{
  "message": "Trip started successfully",
  "trip": { "id": "uuid", "status": "ongoing", ... }
}
```

<CodeGroup>
```typescript Next.js
const { data, error } = await supabase.functions.invoke('start-trip', {
  body: { driver_id: userId, trip_id: tripId }
})
```

```dart Flutter
final res = await supabase.functions.invoke('start-trip', body: {
  'driver_id': userId,
  'trip_id': tripId,
});
```

</CodeGroup>

### Errors

| Status | Message                                                               |
| ------ | --------------------------------------------------------------------- |
| 400    | Some passengers are not verified (returns list of pending passengers) |
| 400    | No confirmed bookings for this trip                                   |
| 403    | Unauthorized: driver mismatch                                         |
| 400    | Trip cannot be started from status `{current_status}`                 |

<Note>
  If unverified passengers remain, the response includes a `pending_passengers`
  array with their names and phone numbers so the driver can contact them or
  mark them as no-shows before starting.
</Note>

## complete-trip

Marks a trip as complete and creates a payout record for the driver. Automatically credits the driver's wallet if their payout preference is `auto`.

**Who can call:** Driver who owns the trip

### Request

```json
{
  "driver_id": "uuid",
  "trip_id": "uuid"
}
```

### Response

```json
{
  "message": "Payout scheduled successfully",
  "payout_id": "uuid"
}
```

<CodeGroup>
```typescript Next.js
const { data, error } = await supabase.functions.invoke('complete-trip', {
  body: { driver_id: userId, trip_id: tripId }
})

const payoutId = data?.payout_id

````

```dart Flutter
final res = await supabase.functions.invoke('complete-trip', body: {
  'driver_id': userId,
  'trip_id': tripId,
});

final payoutId = res.data['payout_id'];
````

</CodeGroup>

### What Happens Internally

1. Checks no payout already exists for this trip
2. Fetches all `accepted` + `paid` bookings
3. Checks for any open disputes (holds payout if found)
4. Fetches driver's active bank account
5. Calculates total payout from `driver_credit_kobo` across all bookings
6. Creates a `payouts` record
7. Links `payout_id` to all bookings and marks them `completed`
8. If driver payout preference is `auto`, credits wallet immediately

### Errors

| Status | Message                               |
| ------ | ------------------------------------- |
| 400    | No bookings to payout                 |
| 200    | Active dispute exists, payout on hold |
| 200    | Payout already scheduled              |
| 400    | Driver bank account not found         |
