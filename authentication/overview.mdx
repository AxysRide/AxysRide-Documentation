# Authentication

AxysRide uses **Supabase Auth** with Email/Password and Phone/OTP. On signup, the database automatically creates a `profiles` row and an empty `wallets` row for the new user via a trigger.

---

## Sign Up

<Warning>
  `full_name` and `phone` are **required** at signup. The `handle_new_user`
  trigger uses these to create the `profiles` row automatically. If either is
  missing, the trigger will throw an error and the signup will fail.
</Warning>

<CodeGroup>
```typescript Next.js
const { data, error } = await supabase.auth.signUp({
  email: 'user@example.com',
  password: 'password123',
  options: {
    data: {
      full_name: 'John Doe',       // required
      phone: '+2348012345678',     // required — include country code
    }
  }
})

if (error) console.error(error.message)

// data.user contains the new user
// data.session contains the JWT

````

```dart Flutter
final AuthResponse res = await supabase.auth.signUp(
  email: 'user@example.com',
  password: 'password123',
  data: {
    'full_name': 'John Doe',       // required
    'phone': '+2348012345678',     // required — include country code
  },
);

final user = res.user;
final session = res.session;
````

</CodeGroup>

<Note>
  After signup, a `profiles` row and `wallets` row are created automatically by
  the `handle_new_user` database trigger using the `full_name` and `phone`
  values passed in `user_metadata`. You do not need to create these manually.
</Note>

<CodeGroup>


</CodeGroup>

## Phone / OTP Sign In

<CodeGroup>
```typescript Next.js
// Step 1 — Send OTP
await supabase.auth.signInWithOtp({ phone: '+2348012345678' })

// Step 2 — Verify OTP
const { data, error } = await supabase.auth.verifyOtp({
phone: '+2348012345678',
token: '123456',
type: 'sms',
})

````

```dart Flutter
// Step 1 — Send OTP
await supabase.auth.signInWithOtp(phone: '+2348012345678');

// Step 2 — Verify OTP
final AuthResponse res = await supabase.auth.verifyOTP(
  phone: '+2348012345678',
  token: '123456',
  type: OtpType.sms,
);
````

</CodeGroup>

## Listen to Auth State Changes

<CodeGroup>
```typescript Next.js
supabase.auth.onAuthStateChange((event, session) => {
  if (event === 'SIGNED_IN') {
    console.log('User signed in:', session?.user)
  }
  if (event === 'SIGNED_OUT') {
    // redirect to login
  }
})
```

```dart Flutter
supabase.auth.onAuthStateChange.listen((data) {
  final AuthChangeEvent event = data.event;
  final Session? session = data.session;

  if (event == AuthChangeEvent.signedIn) {
    // navigate to home
  }
  if (event == AuthChangeEvent.signedOut) {
    // navigate to login
  }
});
```

</CodeGroup>

---

## Session Persistence

Supabase automatically persists the session locally. On app restart, the session is restored automatically — you do not need to manually handle token storage.

---

## User Roles

After signing in, fetch the user's profile to determine their role:

<CodeGroup>
```typescript Next.js
const { data: profile } = await supabase
  .from('profiles')
  .select('role, full_name, avatar_url')
  .single()

// profile.role will be 'passenger' or 'driver'

````

```dart Flutter
final profile = await supabase
    .from('profiles')
    .select('role, full_name, avatar_url')
    .single();

final role = profile['role']; // 'passenger' or 'driver'
````

</CodeGroup>

<Warning>
  Admin users do not appear in the `profiles` table with admin roles. They are
  stored in the `super_admins` table. The admin dashboard (Next.js) checks admin
  status via Edge Functions, not via the `profiles` role column.
</Warning>
